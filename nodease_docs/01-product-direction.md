# 제품 방향

## 원문 피드백의 핵심

메모의 중심 메시지는 "n8n처럼 노드를 연결하는 데모"에서 멈추지 말고, 기업이 실제로 AI 워크플로우를 운영할 때 생기는 문제를 제품에 반영하라는 것이다.

특히 다음 질문에 답해야 한다.

- 어떤 모델을 누가 사용할 수 있는가?
- 특정 데이터는 어떤 부서나 역할만 접근해야 하는가?
- LLM 호출 비용은 어디서 얼마나 발생하는가?
- 실패하면 어느 노드, 어느 모델, 어느 데이터에서 실패했는가?
- RAG 데이터가 계속 바뀌면 색인은 어떻게 갱신하는가?
- PII나 민감정보가 모델로 넘어가기 전에 어떻게 막는가?
- 배포 후에도 정책, 모델, 비용 한도를 조정할 수 있는가?
- 실행 이력을 감사할 수 있는가?

## 제품 포지셔닝

### 기존 인식

Nodease가 단순히 아래처럼 보이면 약하다.

- 노드 기반 AI 자동화 도구
- n8n 스타일 워크플로우 빌더
- 프롬프트를 연결해 실행하는 데모
- 드래그 앤 드롭 편집기

### 목표 인식

Nodease는 아래처럼 보여야 한다.

- 기업용 AI Workflow 운영 플랫폼
- LLMOps Gateway가 내장된 워크플로우 빌더
- AI 워크플로우의 설계, 검증, 배포, 감사 도구
- 비용/품질/보안 정책을 함께 관리하는 AI 운영 콘솔
- 데이터 거버넌스와 RAG 운영 문제를 다루는 플랫폼

## 근거 수준

| 수준 | 의미 | 이 문서에서의 처리 |
| --- | --- | --- |
| 원문 직접 요구 | `memo.md`의 원문 메모에 반복적으로 등장 | 제품 중심축으로 둔다 |
| 원문에서 파생된 해석 | 원문 표현을 제품 기능으로 구체화한 것 | 기능 후보로 두되 우선순위를 조절한다 |
| ChatGPT 요약 확장 | `memo.md` 안의 요약 섹션에 주로 등장 | 발표 메시지나 후속 리서치 후보로 둔다 |

원문 직접 요구가 가장 강한 축은 LLMOps Gateway, audit, RBAC, RAG 데이터 갱신, 비용/품질 최적화, 에디터 UX다. 멀티에이전트는 ChatGPT 요약에서 강하게 등장하지만 원문 직접 키워드는 아니므로, 제품 중심 메시지로 고정하기보다는 워크플로우/에이전트 실행을 설명할 때 보조적으로 사용한다.

## 핵심 가치 제안

| 가치 | 설명 |
| --- | --- |
| Governance | 데이터, 모델, 사용자 권한, 비용 정책을 중앙에서 관리 |
| Reliability | 실패 지점 추적, 재시도/복구 전략, 실행 재현성 제공 |
| Auditability | 모든 실행/수정/배포/승인 이벤트를 감사 로그로 저장 |
| Optimization | 모델, 프롬프트, 청크 전략을 비용과 품질 기준으로 비교 |
| Extensibility | MCP, 외부 DB, 내부 시스템, 커스텀 도구 연결 |
| Enterprise UX | 편한 에디터 위에 운영/정책/감사 기능을 자연스럽게 결합 |

## 사용자 관점

### 워크플로우 빌더

- 노드를 쉽게 연결하고 테스트한다.
- property settings를 빠르게 이해하고 수정한다.
- 모델과 프롬프트를 비교한다.
- 실패한 노드를 빠르게 확인한다.
- 추천된 저비용 모델이나 청크 설정을 적용한다.

### 운영자 / 관리자

- 모델 사용 권한을 제한한다.
- 프로젝트별 비용 한도를 설정한다.
- 배포 후 실행 로그와 비용을 확인한다.
- 장애나 실패 구간을 추적한다.

### 보안 / 컴플라이언스 담당자

- 데이터 소스별 접근 권한을 관리한다.
- PII/Confidential 데이터가 외부 모델로 나가지 않게 통제한다.
- 누가 어떤 데이터를 어떤 모델에 보냈는지 감사한다.
- GDPR audit 준비를 중심으로, HIPAA/ISMS-P 같은 규제 확장 가능성을 확인한다.

## 발표 메시지

Nodease는 AI 워크플로우를 만드는 도구에서 한 단계 더 나아가, 기업이 AI 워크플로우를 운영할 때 필요한 LLM Gateway, 데이터 거버넌스, 감사 로그, 비용 최적화, 신뢰성 기능을 하나의 캔버스 경험 안에 통합한다.
