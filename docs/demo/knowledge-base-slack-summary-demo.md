# Knowledge Base 기반 온보딩 요약 Slack 전달 시연 시나리오

Status: Draft

## 1. 시연 개요

- **주제**: Nodease Knowledge Base의 온보딩 문서를 요약해 Slack 채널에 전달하는 AI 업무 자동화
- **목표 시간**: 4분 내외
- **핵심 메시지**: 사용자는 자연어로 workflow를 만들고, Nodease는 Knowledge Base 권한 안에서 실행하며, 관리자는 실제 비용 비교와 감사 이력으로 운영을 통제한다.

이 시나리오는 Nodease가 직접 관리하는 Knowledge Base와 RBAC 범위로 한정한다. MCP, SSO 또는 외부 원본 시스템의 ACL을 유지·동기화하는 기능은 전제하지 않는다.

## 2. 사전 준비

| 구분 | 설정 |
| --- | --- |
| 지민 | 개발팀 일반 사용자. workflow 생성과 `개발팀 온보딩` Knowledge Base 사용 권한 보유 |
| 태훈 | 타 팀 일반 사용자. 해당 Knowledge Base 사용 권한 없음 |
| 민아 | 조직 관리자. 비용, 감사 로그, 사용자 접근 관리 가능 |
| Knowledge Base | 개발환경 설정, 배포 절차, 코드리뷰 가이드, 신규 입사자 FAQ 등 저민감도 문서 |
| 외부 연결 | `#new-hires` Slack 채널과 승인된 LLM·Slack credential 연결 |
| 비용 비교 | 같은 LLM 노드의 성공한 baseline 실행 로그와 후보 모델 준비 |

credential 원문, token, 원본 문서 전문은 시연 화면과 trace에 표시하지 않는다. 운영 이상 경보 기능이 구현되지 않았다면 4단계의 경보는 사전 준비한 목표 UX 예시로만 시연한다.

## 3. 4분 시연 흐름

### 1단계. 문제와 자연어 생성 — 45초

**화면 조작**

지민이 Agent Builder에 다음 요청을 입력한다.

```text
매주 월요일 오전 9시에 개발팀 온보딩 Knowledge Base에서
개발환경 설정과 배포 절차를 찾아 신규 입사자가 알아야 할 핵심 세 가지로 요약해
#new-hires 채널에 보내는 workflow를 만들어줘.
```

AI는 별도 `미리보기` 버튼을 요구하지 않고, 응답과 동시에 저장 전 초안 graph를 캔버스에 표시한다.

```text
[Schedule Trigger: 매주 월요일 09:00]
  → [Knowledge Base 검색]
  → [LLM 요약]
  → [Slack 전송]
```

AI는 필요한 항목만 묻는다.

> “코드리뷰 가이드도 요약 대상에 포함할까요?”
>
> “Slack 채널은 `#new-hires`가 맞나요?”

지민이 답하면 필터와 Slack 설정이 초안에 반영된다.

**발표 문구**

> 사용자는 노드를 조립하지 않고 원하는 업무를 말합니다. AI가 바로 workflow를 그리고, 필요한 선택지만 대화로 확인합니다.

### 2단계. 이해 가능한 설정과 실행 — 55초

**화면 조작**

`LLM 요약` 노드를 선택해 “신입 구성원이 읽을 세 가지 핵심 항목을 정리한다”는 설명과 모델·요약 길이 설정을 짚는다. `Knowledge Base 검색` 노드에서는 “허용된 온보딩 문서에서만 근거를 찾는다”는 설명을 확인한다.

지민이 `적용 및 저장`을 선택한 뒤, 미리 준비한 `개발환경 설정`·`배포 절차` 문서를 대상으로 테스트 실행한다. 결과 화면에서 요약, 안전한 citation 요약, Slack 전달 성공 상태를 한 번에 확인한다.

**발표 문구**

> AI 초안은 바로 확인할 수 있지만, 저장할 때는 권한과 연결 상태를 다시 검증합니다. 사용하기 쉽고, 실제 실행은 통제됩니다.

### 3단계. 실제 A/B 권한 경계와 비용 최적화 — 85초

**화면 조작**

지민 계정에서는 `개발팀 온보딩` Knowledge Base를 사용한 실행이 성공하는 모습을 보여 준다. 이어 태훈 계정으로 전환해 같은 Knowledge Base를 선택할 수 없거나 API에서 차단되는 모습을 짧게 보여 준다. 권한 없는 문서의 제목·내용·개수는 보이지 않는다.

다시 지민 화면에서 LLM 요약 노드의 Cost Optimizer를 열고, 성공한 baseline 실행 로그를 직접 선택한다. 같은 입력으로 B 후보를 실행해 아래 결과만 비교한다.

| 항목 | A안 | B안 |
| --- | ---: | ---: |
| 모델 | 고성능 모델 | 경량 모델 |
| 실행 비용 | 예시: $0.024 | 예시: $0.014 |
| 결과 | 기준 실행 | 적용 후보로 적합 여부 |

비용, 토큰, 출력 품질, downstream 호환성을 확인한 뒤 B안을 현재 LLM 노드 draft에 적용한다.

**발표 문구**

> 지민은 허용된 Knowledge Base만 사용할 수 있고, 태훈은 같은 문서를 검색할 수 없습니다. 비용 최적화도 단순 경고가 아닙니다. 같은 입력에서 실제로 어떤 모델이 얼마를 절감하면서 사용할 수 있는 결과를 내는지 비교한 뒤 적용합니다.

### 4단계. 관리자 경보와 조치 — 45초

**화면 조작**

민아가 Slack에서 반복 실행 경보를 받는다.

```text
[Nodease 운영 경보]
워크플로우: 온보딩 문서 요약 및 Slack 전달
사용자: 지민
최근 10분 실행: 80회
[실행 상세 보기]
```

상세 보기에서 실행 이력, 실제 사용 모델, 비용, redaction-safe audit log를 확인한다. 민아는 지민의 조직 멤버십을 일시 정지하거나 Knowledge Base 사용 권한을 회수한다. 조치 결과가 audit log에 남는 것을 확인한다.

**발표 문구**

> 관리자는 화면을 계속 감시하지 않습니다. 경보에서 실행 상세로 이동해 원인을 확인하고, 사용자를 정지하거나 권한을 회수한 뒤 그 조치까지 감사할 수 있습니다.

### 5단계. 마무리 — 10초

> Nodease는 자연어 기반 AI Builder, Knowledge Base 권한 제어, 로그 기반 비용 최적화, 감사 가능한 운영 대응을 하나의 업무 자동화 흐름으로 제공합니다.

## 4. 기능 연결과 시연 범위

| 기능 | 시연 장면 |
| --- | --- |
| Agent Builder | 요청 즉시 초안 graph를 시각화하고, 필요한 선택지만 질의한다. |
| Workflow 저장 경계 | `적용 및 저장`에서 권한·validation을 재확인한다. |
| Knowledge/RAG와 RBAC | 지민·태훈 계정으로 허용·차단 결과를 비교한다. |
| LLM credential | 연결 상태만 보여 주고 secret은 노출하지 않는다. |
| Cost Optimizer | 같은 baseline 입력으로 후보 모델의 비용·품질·호환성을 비교한다. |
| Audit/Trace | 저장, 실행, 권한 변경의 safe summary를 확인한다. |
| 운영 경보 | Slack 경보에서 실행 상세와 정지·권한 회수 조치로 이동한다. |

## 5. 시연 시 주의사항

- 이 workflow의 `Schedule Trigger`는 매주 월요일 오전 9시에 실행하는 정기 trigger다. 문서 변경을 감지하거나 외부 문서의 수정 시각을 조회하는 기능이라고 설명하지 않는다.
- 예산 제한, abuse·anomaly 탐지, 비용 최적화는 서로 다른 개념이다. 비용 최적화는 반드시 실제 비교 실행 또는 실제 모델 라우팅 결과의 근거로 설명한다.
- 이상 탐지·Slack 운영 경보가 아직 구현되지 않았다면 현재 기능인 것처럼 말하지 않는다. 이 경우에는 “목표 운영 UX”임을 명시하고, 구현된 audit access action만 실제로 시연한다.
- 외부 DB·SaaS 권한 연동이나 원본 ACL의 single source of truth를 제공한다고 주장하지 않는다.
