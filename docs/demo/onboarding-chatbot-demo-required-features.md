# 팀별 온보딩 챗봇 데모에 필요한 기능

Status: Draft

## 목적

개발팀 사용자 A와 기획팀 사용자 B가 같은 온보딩 질문을 했을 때, 각자 권한이 있는 문서만 검색하는 챗봇 데모를 위한 구현·구성 항목을 정리한다. 데모에는 AI Builder, 모델 라우팅, 비용 근거, 감사로그, 이상 징후 대응, 사용자 정지가 포함된다.

## P0 — 데모 성립에 필수

### 1. 인증 기반 내부 챗봇 배포

- 로그인한 사내 사용자만 접근하는 챗봇 배포 유형이 필요하다.
- 공개 챗봇과 비공개 Knowledge Base를 함께 사용할 수 없는 제약을 해소해야 한다.
- 실행 주체를 workflow 실행 컨텍스트에 전달해 KB 권한 필터에 사용해야 한다.

### 2. 팀별 RAG 문서 접근 제어

- 공통 온보딩 KB, 개발팀 온보딩 KB, 기획팀 온보딩 KB를 분리한다.
- workflow에는 세 KB를 연결하고, 실행 사용자의 팀·직접 권한에 따라 허용된 KB만 검색한다.
- 권한 없는 문서의 제목, 내용, 개수, citation은 결과에 노출하지 않는다.

### 3. A/B 사용자·팀·권한 데모 데이터

- 개발팀 사용자 A와 기획팀 사용자 B를 준비한다.
- 팀별 KB 권한, workflow 실행 권한, LLM Credential 사용 권한을 설정한다.
- 동일한 질문에 대해 팀별로 서로 다른 검색 결과가 나오는 문서 데이터를 준비한다.

### 4. 질문 복잡도 기반 모델 라우팅

- 단순 검색 질문은 저비용 모델로, 규정 충돌·비교·예외 판단은 고성능 모델로 보내는 기준이 필요하다.
- 제품 기능으로 자동 판단을 주장하려면 `query_complexity` 또는 `reasoning_tier` 분류 기능을 구현한다.
- 4분 데모에서는 검증된 사전 라우팅 정책을 사용할 수 있다. 이 경우 실시간 학습이 아니라 과거 로그로 검증된 정책이라고 설명한다.

### 5. 실제 라우팅·비용 근거 표시

- 선택된 모델, 선택 이유, 적용 규칙, 토큰·비용을 실행 결과에서 보여 준다.
- 기본 고성능 모델 대비 예상 절감액과 품질 평가 결과를 함께 표시한다.
- 단순 자동 라우팅 활성화만으로 비용 최적화라고 설명하지 않는다.

### 6. 조직 단위 감사로그 정합성

- 실행, RAG, 배포 감사 이벤트에 `organization_id`를 포함한다.
- 관리자 감사 화면에서 방금 실행한 이벤트를 조직 기준으로 조회할 수 있어야 한다.
- 사용자, workflow, KB, 선택 모델, 비용, 조치 이력을 안전한 메타데이터로 연결한다.

### 7. 이상 탐지 → Incident → 알림 흐름

- 예: 동일 사용자가 60초 안에 정해진 횟수 이상 실행하면 이상 징후로 탐지한다.
- Incident 생성 및 `open`, `acknowledged`, `resolved` 상태 관리가 필요하다.
- Slack 또는 이메일 알림을 전송하고, 중복 알림을 방지한다.
- 알림에서 권한이 확인된 Incident 상세 화면으로 이동할 수 있어야 한다.

### 8. 관리자 대응: 사용자 정지

- Incident 상세에서 사용자 실행 이력과 관련 감사로그를 확인한다.
- 관리자가 조직 멤버십을 정지하거나 권한을 회수할 수 있어야 한다.
- 조치 결과는 감사로그에 기록한다.

## P1 — AI Builder와 시연 완성도

### 9. AI Builder 즉시 시각화

- 사용자가 “만들어줘” 또는 “그려줘”라고 요청하면 저장 전 workflow graph를 즉시 캔버스에 표시한다.
- 별도 미리보기 버튼을 요구하지 않는다.
- KB, 모델, 채널 등 빠진 정보만 대화형으로 질문한다.

### 10. 초보자용 노드 설명

- Knowledge 노드: 검색할 사내 문서 범위
- LLM 노드: 검색 결과를 바탕으로 답변을 만드는 모델
- Router 노드: 질문 복잡도에 따른 모델 선택 기준
- Answer 노드: 최종 답변과 출처 전달

중요 속성은 내부 키가 아니라 사람이 이해할 수 있는 이름과 설명으로 표시한다.

### 11. 답변 출처와 불확실성 표시

- 답변에 참조 문서명과 안전한 citation 요약을 표시한다.
- 휴가 규정과 프로젝트 운영 규정의 우선순위가 문서에 없으면 임의로 결론 내리지 않고 담당 부서 확인이 필요하다고 안내한다.
- 복잡 질문에 대한 기대 답변과 평가 세트를 준비한다.

### 12. 데모 재현성

- 초기화 가능한 시드 데이터와 사전 배포된 workflow를 준비한다.
- 라우팅 정책, baseline 실행 로그, 비용 비교 결과를 사전 준비한다.
- LLM Credential과 외부 알림 연결을 점검하되 secret 원문은 화면·로그·문서에 노출하지 않는다.
- 실시간 이상 탐지가 아직 구현되지 않았다면 이를 실시간 기능처럼 표현하지 않고 Incident 대응 UX 예시로 범위를 한정한다.

## 4분 데모 우선순위

1. 인증된 내부 챗봇에서 A/B 사용자별 RAG 권한 차이를 시연한다.
2. 단순 질문과 규정 충돌 질문에 적용된 모델·비용·선택 근거를 보여 준다.
3. 감사로그에서 실행을 추적하고 Incident 알림을 통해 관리자 화면으로 이동한다.
4. 관리자 권한으로 사용자 정지를 수행하고 조치 이력을 확인한다.

P0 항목이 준비되지 않은 경우, 해당 기능을 실제 동작처럼 시연하지 않는다. 특히 사전 생성된 Incident와 사전 구성된 라우팅 정책은 각각 Incident 대응 UX와 검증된 정책 적용으로 명확히 설명한다.
