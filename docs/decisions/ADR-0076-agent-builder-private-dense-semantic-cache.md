# ADR-0076: Agent Builder Private Dense Semantic Cache

Status: Accepted

Amends on acceptance: ADR-0063 Decision 3 and Decision 17 only; ADR-0073 and ADR-0074 deterministic normalization boundaries remain unchanged.

Related ADRs: [ADR-0063](ADR-0063-agent-builder-deterministic-intent-plan-cache.md), [ADR-0073](ADR-0073-agent-builder-cache-exact-token-normalization-amendment.md), [ADR-0074](ADR-0074-agent-builder-cache-safe-literal-normalization-amendment.md), [ADR-0075](ADR-0075-agent-builder-durable-intent-plan-repository.md)

## Context

ADR-0063~0075의 Agent Builder cache는 결정적으로 동등한 요청만 Redis L1과 encrypted PostgreSQL L2에서 재사용한다. 안전한 literal-preserving normalizer 덕분에 동일한 자연어 요청은 exact cache에 참여할 수 있지만, 표현만 달라진 요청은 Planner를 호출한다.

개인 범위에서만 과거 cache-safe intent plan을 후보로 찾으면 반복되는 유사 요청의 Planner 호출을 줄일 수 있다. 그러나 vector similarity는 target, 부정, 순서, 조건 또는 explicit parameter 차이를 동등성으로 증명하지 못한다. 과거 GraphMutation, protected resource identity, authorization decision, raw request 또는 provider payload를 검색·재생하는 설계는 기존 cache와 direct-edit/CAS 경계를 깨뜨린다.

JEO-8은 GraphRAG, workflow template recommendation, organization/shared cache, public API와 Client UI를 추가하지 않는다. 이 결정은 semantic foundation과 additive migration을 허용하되, 승인된 Agent Builder embedding authority가 생기기 전까지 live provider composition과 semantic serving은 기본 비활성으로 유지한다.

## Decision

1. Dense semantic cache는 exact equality를 확장하거나 normalizer를 바꾸지 않는다. 인증, active organization, Agent Builder permission, request admission과 cancellation/version fence 뒤에 기존 safe normalization을 실행하고, Redis L1 exact lookup과 L1 miss 뒤의 JEO-7 L2 exact lookup이 각각 명시적 `miss`일 때만 semantic candidate assist를 고려한다. L1 또는 L2 hit은 embedding, vector retrieval과 semantic verifier를 호출하지 않고 기존 rehydration 경로를 사용한다. L2 `None|invalid|unavailable`, disabled, `write_only`, allowlist 밖과 schema-unready는 semantic-eligible miss가 아니며 semantic provider/repository/verifier/index call을 모두 건너뛴다.
2. Semantic candidate assist는 개인 범위이며 target-independent `new_workflow` 요청에만 허용한다. `selected_target`이 있거나 request/draft type이 modify/replace인 요청은 exact L1/L2 miss 뒤에도 embedding, semantic lookup, index append와 semantic serving을 모두 건너뛰고 기존 single-flight Planner path를 따른다. 모든 semantic SQL read/write는 `organization_id`와 `user_id`를 함께 predicate로 사용하며, semantic index의 organization/user scope와 referenced L2 record의 organization scope는 composite FK로 DB에서도 일치시킨다. 같은 organization의 다른 user, 다른 organization 또는 다른 generation mode의 row는 후보가 될 수 없다.
3. Embedding 입력은 `SemanticQueryProjectionV1`뿐이다. 이 transient DTO는 secret/redaction, truncation, explicit parameter value, malformed quote와 target-independent-new-workflow gate 뒤에 versioned `summary.current_safe_message.v1` redaction projection을 적용한 bounded text와 projection version만 가진다. Whitespace/redaction-cleaned projection이 240 code point를 초과하면 first-240 slice를 semantic input으로 사용하지 않고 semantic-ineligible `miss`로 Planner에 진행한다. Exactly 240 code point까지만 허용한다. Projection 부재, redaction marker 또는 version mismatch도 provider 호출 없이 Planner로 진행한다. `full_safe_message`와 normalizer 내부 문자열을 provider port에 직접 넘기지 않는다. Raw request/query text, graph, node/edge UUID, credential/Knowledge/Connection identity, explicit parameter 값, permission decision과 raw provider payload는 DB, log, metric, trace, audit와 fixture에 남기지 않는다. Durable semantic data는 redaction을 통과한 embedding, safe scope/version metadata와 encrypted L2 record FK뿐이며 projection text는 저장하지 않는다. Embedding은 의미를 가진 파생 민감 데이터로 취급한다.
4. Semantic index row는 organization/user scope, generation mode, semantic query projection version, embedding profile/model version, planner/catalog/normalizer contract version, required cache-safe rehydration contract version, safe query embedding, L2 record FK, created_at와 expires_at를 가진다. L2 plan envelope를 복제하지 않는다. L2의 `created_at`과 immutable 30-day `expires_at`이 plan과 intended lifecycle authority이며 성공적으로 insert/replacement된 usable index row에는 같은 expiry를 복사한다. Existing L2 retention task는 만료 semantic child를 bounded batch와 delete-time expiry recheck로 직접 hard-delete한 뒤 만료 parent를 삭제하고, parent delete의 FK `ON DELETE CASCADE`도 남은 semantic row를 함께 삭제한다. Expired parent가 같은 ID로 갱신된 뒤 best-effort child replacement가 실패하면 old child는 mismatch/expiry filter로 즉시 non-retrievable하고 다음 retention run에서 삭제되어 이전 embedding을 갱신된 parent expiry까지 보존하지 않는다.
5. Vector repository는 pgvector adapter 뒤의 application port다. Search SQL은 vector ordering 전에 organization/user, generation mode, semantic query projection version, embedding profile/model, planner/catalog/normalizer와 required rehydration contract versions, index expiry, referenced L2 expiry를 모두 `WHERE`으로 제한하고 top-k만 반환한다. Similarity score는 후보 정렬용 transient 값일 뿐 durable telemetry가 아니며, model, dimension, top-k와 threshold의 production 값은 코드나 ADR에 고정하지 않는다. Configuration이 완전하지 않으면 semantic cache를 비활성화한다.
6. Similarity만으로 cached plan을 반환하지 않는다. Joined L2 envelope를 strict decode한 후보는 verifier와 rehydrator 전에 `request_type=new_workflow`, `draft_mode=new_workflow`, `edit_placement=null`을 모두 만족해야 한다. 부적격 후보는 다음 후보로 진행하고 유효 후보가 없으면 Planner로 fallback한다. 적격 후보도 transient semantic verifier가 명시적으로 `verified`를 반환하고, 기존 current model/credential use permission, target-independent workflow context, Catalog, Knowledge/Collection permission·lifecycle·readiness rehydration을 모두 통과할 때만 재사용한다. verifier의 `rejected|uncertain|unavailable|error`, vector/embedding 오류, candidate decode/expiry 오류 또는 rehydration 실패는 후보를 버리고 기존 Planner를 한 번 수행하는 fail-open 경계다.
7. `semantic_candidate_assist`와 `planner_free_semantic_serving`은 별도 flag다. Assist는 candidate retrieval/verification을 관찰·검증할 수 있으나 Planner 호출을 생략하지 않는다. Serving은 기본 비활성이고, 명시적으로 enabled이며 provider-call-free verifier가 `verified`를 반환할 때만 Planner를 생략할 수 있다. 이 이름은 Planner 생략만 뜻하며 query embedding은 승인된 external provider I/O와 usage attribution을 여전히 요구할 수 있다. Verifier가 없거나 provider I/O가 필요하거나 결과가 불확실하면 serving은 Planner를 생략하지 않는다.
8. JEO-8은 embedding/verifier ports와 fake 기반 TDD를 제공하지만 live production embedding/provider-backed verifier adapter를 조합하지 않는다. 기존 deployment/node-bound `query_embedding` capability를 Agent Builder 요청에 재사용하거나 환경 설정의 credential로 provider를 직접 호출하는 것은 금지한다. 별도 승인된 Agent Builder `query_embedding` capability/profile과 durable usage binding이 준비된 뒤에만 `SemanticExternalCallAdmissionPort` production composition을 추가할 수 있다. Admission의 `admitted` 결과는 목적이 `query_embedding|semantic_verification` 중 하나인 opaque, immutable, non-serialized `SemanticExternalCallBinding`을 필수로 가지며 `denied|unavailable`은 binding을 가질 수 없다. Embedding provider는 `query_embedding` binding 없이는 호출할 수 없고 provider-backed verifier는 별도의 `semantic_verification` admission/binding을 요구한다. 그 adapter는 독립된 짧은 Session에서 current actor/organization, model·credential `use`, lifecycle과 usage attribution을 확인해야 한다. Provider-backed verifier는 assist에서만 같은 authority를 사용할 수 있고, planner-free serving에는 provider-call-free verifier만 허용한다. Authority 또는 binding 부재·실패·불확실성은 외부 semantic provider 호출 없이 기존 Planner path로 fail-open한다.
9. JEO-7 transaction clean-boundary를 semantic I/O에도 적용한다. Service DB transaction 또는 connection을 보유한 채 embedding provider, Planner provider, Redis 또는 별도 semantic repository session을 기다리지 않는다. Semantic 처리 중 guard가 한 번이라도 clean boundary를 만들지 못하면 보유한 transient embedding을 append에 재사용하지 않고 해당 요청의 semantic 후속 I/O를 모두 중단한다. Candidate rehydration 뒤에는 Planner 또는 L1 promotion 전에 service read transaction을 정리한다. 정리할 수 없으면 provider/Planner/cache write를 호출하지 않고 bounded `SemanticTransactionBoundaryError`로 종료한다.
10. L1/L2 usable double miss 뒤에는 기존 JEO-7 single-flight lease를 먼저 획득한다. Lease owner만 embedding, vector retrieval, verifier와 candidate rehydration을 수행하며 follower는 semantic I/O를 중복하지 않고 기존 follower 계약을 따른다. Admission, embedding, vector lookup과 verifier 같은 semantic external boundary 뒤에는 cancellation/request-version fence를 다시 확인한다. Candidate rehydration/serving과 fallback Planner 직전에도 다시 확인하며 `canceled|stale`이면 Planner, L1/L2, semantic append 없이 기존 terminal contract로 종료한다. Planner-free semantic serving으로 검증·rehydration된 결과는 현재 exact key에 `save_if_lease_owner`로 L1 승격을 시도한 뒤 반환한다. 이 L1 write가 실패해도 owner의 검증된 결과는 반환할 수 있으나 follower에는 completion value를 주지 않아 기존 Planner fallback을 유지한다.
11. Planner 결과의 strict `CachedIntentPlanV1` projection과 independent L2 commit이 `stored`이고 같은 owner execution에 이미 transient safe embedding이 있는 경우에만 semantic index write를 한 번 best-effort로 시도한다. Planner 뒤에 embedding을 새로 호출하지 않는다. 기존 Redis `IntentPlanSaveResult`는 변경하지 않는다. L2 port는 strict `IntentPlanL2SaveResult`를 반환하며 `stored`일 때만 opaque, non-serialized `IntentPlanL2StoredReceipt(parent_record_id, expires_at, write_kind)`가 필수다. `unavailable`은 receipt 없이 `cache_unavailable`만 가진다. L2 repository는 같은 짧은 independent transaction에서 unique row를 lock하고 DB가 확인한 실제 parent record ID, immutable `expires_at`과 `inserted|unexpired_conflict|expired_replacement` write kind를 receipt로 반환한다. Missing-row insert는 `ON CONFLICT DO NOTHING RETURNING`을 사용하고 concurrent insert loser만 같은 transaction에서 한 번 `SELECT ... FOR UPDATE`로 authoritative row를 확인한다. Post-commit re-read, 추정 ID, 현재 시간 대체와 unbounded retry는 금지한다. L2 write failure, unavailable result, receipt 부재 또는 transient embedding 부재면 semantic index write를 하지 않는다. Semantic index write failure는 L2, existing L1 promotion 또는 valid Planner response를 rollback하거나 실패시키지 않는다.
12. Migration은 JEO-7 L2 plan row를 재설계하지 않는 additive change다. It adds the semantic index, its scope/version/expiry lookup index, parent organization composite candidate key needed for the composite FK, organization/user cascade, L2 parent cascade and a downgrade guard that refuses while semantic rows remain. Semantic append는 현재 `IntentPlanningContext.organization_id`와 receipt의 parent ID/expiry가 같은 SQL의 parent predicate와 일치할 때만 수행한다. `inserted`와 `unexpired_conflict`는 child가 없으면 insert하고 existing unique conflict는 `DO NOTHING`이다. `expired_replacement`는 child가 없으면 insert하고, 있으면 existing child expiry가 receipt expiry보다 과거일 때만 embedding, created_at와 expires_at을 원자적으로 conditional update한다. Parent expiry mismatch, same/newer child와 늦은 receipt는 zero-write다. Existing L2 retention task는 semantic child expiry를 먼저 bounded purge하고 semantic table/column readiness 오류는 savepoint 또는 별도 짧은 transaction에서 child 단계만 rollback한 채 parent purge를 계속한다. Child readiness는 process-lifetime flag를 남기지 않고 매 Beat 실행에서 다시 시도한다. Child와 parent를 각각 bounded batch로 처리하고 어느 한쪽이 full limit이면 기존 최대 5회 loop를 계속한다. Semantic repository readiness failure도 existing L1/L2/Planner behavior를 disable하지 않는다. The JEO-8 downgrade executes before the existing JEO-7 L2 downgrade guard. Redis/audit/request history backfill, a new retention worker and a new public cache endpoint are forbidden.
13. Existing `agent_builder_requests.intent_cache_outcome` allowlist를 바꾸지 않는다. Planner-free semantic serving으로 Planner를 생략하면 `hit`, semantic assist/reject/no-candidate/current-rehydration reject 뒤 Planner를 호출하면 `miss`, embedding/vector/verifier infrastructure 또는 semantic schema readiness 오류 뒤 Planner를 호출하면 `error`다. Semantic feature/config/provider authority가 비활성이라 semantic flow를 시작하지 않으면 기존 exact-cache outcome을 유지한다. Terminal rollback 뒤에도 이 allowlisted outcome을 JEO-7 failure commit에서 복원한다. L1/L2/semantic source, candidate identity, vector score, embedding, verifier detail 또는 protected resource information은 저장하지 않는다.

## Consequences

- Exact L1/L2 behavior, L2 DB-first ordering, L2 30-day retention and current rehydration remain the authority for reusable plans.
- A semantic reuse can be Planner-free only for target-independent `new_workflow` after two independent gates: a configured provider-call-free verifier and the existing protected-resource rehydration. Query embedding can still be an admitted provider call with durable usage attribution; all other semantic states retain the Planner path.
- pgvector storage is private and tenant/user constrained; it is not a GraphRAG corpus, template catalog, shared recommendation source or audit/replay record.
- A profile-specific production rollout needs an approved Agent Builder `query_embedding` capability/profile and durable usage binding, dimension/index compatibility, timeout/capacity/failure testing, redaction verification and explicit flags. Until then live semantic assist and serving stay disabled.

## Rejected Alternatives

- **Similarity-only cache hit**: target, parameter, condition and authorization differences can be hidden by a high score.
- **Storing raw normalized text with the vector**: raw user request remains prohibited even after redaction-oriented normalization.
- **Sharing candidates within an organization**: different users can have different current target, credential and Knowledge authority.
- **Copying the L2 plan into the semantic row**: it duplicates encrypted payload lifecycle and makes parent retention non-authoritative.
- **Using semantic retrieval as GraphRAG or template recommendation**: those need their own corpus, ranking, evaluation and product decision.
- **Asynchronous/outbox-only index write before L2 commit**: it can leave an index entry without a durable L2 plan and violates JEO-7 DB-first ordering.
